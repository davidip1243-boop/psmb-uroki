# Школьное расписание

Статическое приложение расписания школы. Рабочая версия находится в `dist/` и не требует Node.js, базы данных или API-сервера во время работы.

## Что здесь есть

- `dist/` — готовый сайт: HTML, CSS и JavaScript.
- `index.html` — запасная корневая страница для хостингов, которые запускают сайт из корня репозитория и затем переходят в `/dist/`.
- `.openai/hosting.json` — метаданные для OpenAI Sites; это не конфигурация Vercel.
- `public/` — генерируемая папка для хостингов, которые ожидают результат сборки в `public/`; она не коммитится.

Приложение сначала показывает расписание, встроенное в `dist/index.html`, а затем обновляет его из Google Sheets. После загрузки страницы оно проверяет таблицу каждые пять минут и повторяет проверку, когда пользователь возвращается на вкладку. Если Google недоступен или запрос не проходит, встроенные данные остаются рабочим резервом. Поэтому доступ к Google не нужен для открытия самого сайта, но без него обновления таблицы в браузере не подгрузятся.

## Локальная проверка

```sh
npm ci
npm run build
```

Скрипт сборки копирует `dist/` в `public/`. Для проверки результата можно открыть `dist/index.html` через любой статический HTTP-сервер или сразу использовать `dist/` как document root.

## Развёртывание на VPS в России через Nginx

Для VPS достаточно Nginx. Запускать Node.js-процесс не требуется.

1. Соберите сайт локально или на сервере:

   ```sh
   npm ci
   npm run build
   ```

2. Загрузите содержимое `dist/` на сервер, например в `/var/www/psmb-uroki/dist/`.

3. Скопируйте `deploy/nginx/psmb-uroki.conf.example` в конфигурацию Nginx, замените `example.ru` на свой домен и проверьте, что путь `root` указывает на каталог `dist`.

4. Проверьте и перечитайте конфигурацию:

   ```sh
   sudo nginx -t
   sudo systemctl reload nginx
   ```

После этого сайт будет доступен напрямую с российского сервера. HTTPS можно добавить отдельно через сертификат Let's Encrypt или сертификат выбранного хостинга.

## Vercel и другие статические хостинги

В репозитории нет активного `vercel.json`; старый файл был удалён. Проект остаётся совместимым со статическим деплоем: команда сборки создаёт `public/`, а исходный готовый артефакт находится в `dist/`. `.openai/hosting.json` используется OpenAI Sites и не переносит сайт автоматически на VPS.

Для Vercel или другого CI нужны только стандартные шаги `npm ci` и `npm run build`; токены и переменные окружения этому приложению не требуются.

После однократного деплоя изменения в публичной вкладке Google Sheets подхватываются автоматически, без новой сборки Vercel. Важно не удалять вкладку с расписанием и сохранять к ней публичный доступ на чтение; сейчас приложение использует `gid=2045912974`.

## Что ещё нужно для реального запуска

Этот репозиторий подготовлен, но фактическая миграция не выполнена: нужны доступ к выбранному российскому VPS/облаку, домен и DNS-доступ. Следующий короткий шаг — выбрать сервер и домен, загрузить `dist/`, включить пример Nginx-конфигурации и направить DNS на IP сервера.
